# 终端监控面板连接时空白问题的解决方案

## 1. 现状回顾
当前 `TerminalMonitor.tsx` 在 SSH 连接过程中以及获取到首份数据前显示为空白。这是由于组件内部采用了严格的条件渲染守卫 `if (!currentSessionData) return null;`，且数据抓取逻辑必须等待背景会话（Background Session）完全就绪后才启动。

## 2. 解决方案建议

### 2.1 引入骨架屏/加载状态 (Skeleton & Loading State)
不应在没有数据时直接返回 `null`，而是根据当前的连接状态展示不同的 UI。

*   **实现思路**：
    *   定义一个 `isLoading` 状态，当 `status === 'connecting'` 或 `currentSessionData` 尚未填充时为 `true`。
    *   在数据加载期间，渲染 `CARD_DESCRIPTORS` 的骨架屏版本（灰色占位块），保持面板布局的稳定性。

### 2.2 放宽渲染守卫 (Relax Rendering Guard)
修改组件底部的渲染判断逻辑。

*   **修改建议**：
    ```typescript
    // 原代码
    if (!sessionId || !currentSessionData) return null;

    // 修改后：只要有会话 ID，就渲染面板外壳
    if (!sessionId) return null;
    ```
    这样即使用户还在连接中，也能看到面板的标题栏和基本的背景结构，提升视觉连续性。

### 2.3 优化初始化轮询时机
目前的轮询必须等待背景会话就绪。可以考虑更早地进行尝试。

*   **实现思路**：
    *   如果主会话已连接（`status === 'connected'`），即可尝试发起第一次数据请求。
    *   在 `MonitorDataService` 中增强错误处理，如果背景会话暂未就绪，静默等待下一次轮询，而不是完全不启动。

### 2.4 状态分级展示
将面板内容分为“静态基础信息”和“动态资源信息”。

*   **实现思路**：
    *   **基础层**：如服务器名称、标题栏，在 `sessionId` 存在时立即显示。
    *   **信息层**：如操作系统信息（OS Info），通常获取极快，可以优先显示。
    *   **资源层**：如 CPU/内存实时曲线，在数据到达后再通过动画淡入。

## 3. 预期效果
*   用户点击连接后，监控面板立即出现并显示“正在连接服务器...”的提示或骨架屏。
*   消除由于组件突然出现/消失导致的布局跳动。
*   提升应用整体的“高级感”和响应速度反馈。
